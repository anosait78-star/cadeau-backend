# دليل مبرمج المتجر — الربط مع Cadeau CRM عبر Storefront Integration API

هذا الدليل عملي، موجّه لمبرمج **المتجر الإلكتروني نفسه** (Salla, Zid, Shopify,
WooCommerce، أو متجر مبني يدويًا) الذي يريد إرسال الطلبات والمنتجات تلقائيًا
إلى Cadeau CRM. للمرجع التقني الكامل (العقود، القرارات المعمارية) راجع
[docs/api/storefront.md](api/storefront.md). هذا الملف يشرح **كيف تستخدم الـ API
بالطريقة الصحيحة خطوة بخطوة**، بدون تفاصيل داخلية غير ضرورية لك كمطوّر متجر.

> **مهم:** هذا الربط **اتجاه واحد فقط** (inbound) — متجرك هو من يرسل الطلبات
> والمنتجات إلى Cadeau. لا يوجد webhook خارج من Cadeau إلى متجرك في هذا الإصدار.

---

## 1. المتطلبات قبل البدء

1. يجب أن تكون خطة الشركة (Plan) تتضمن ميزة `storefront_integration` (متاحة
   في خطة **Pro**). إن لم تكن مفعّلة، اطلب من مالك الحساب (Owner) التواصل مع
   الدعم لتفعيلها — واجهة CRM ستعرض رسالة صريحة في هذه الحالة.
2. يجب أن يقوم **مالك الحساب أو أي مستخدم يملك صلاحية `integrations.manage`**
   (عادة الـ Owner أو Store Manager) بإنشاء "اتصال" (Connection) من داخل CRM
   أولًا — هذا الاتصال هو ما يولّد لك مفتاح الـ API الخاص بمتجرك.
3. أنت — كمبرمج المتجر — لا تحتاج حساب مستخدم في Cadeau أصلًا؛ كل ما تحتاجه
   هو **مفتاح الـ API (API Key)** الذي يُعطيك إياه مالك الحساب بعد إنشاء
   الاتصال.

---

## 2. الحصول على مفتاح الـ API (خطوة يقوم بها صاحب الحساب، وليس أنت)

من إعدادات CRM → **تكامل المتجر الإلكتروني (Storefront Integration)**:

```
POST /v1/integrations/storefront/connections
Authorization: Bearer <JWT الخاص بالمستخدم صاحب الصلاحية>
Content-Type: application/json

{
  "label": "متجر سلة الرئيسي",
  "platform": "salla",              // اختياري: generic | salla | zid | shopify | woocommerce
  "defaultWarehouseId": null         // اختياري: المخزن الذي يُخصم منه المخزون افتراضيًا
}
```

**الرد (مرة واحدة فقط يظهر فيها المفتاح الصريح):**

```jsonc
{
  "id": "1f2c...",
  "label": "متجر سلة الرئيسي",
  "platform": "salla",
  "apiKeyPrefix": "sfk_ab12",
  "apiKey": "sfk_ab12cdEXAMPLEKEYFULLVALUE...", // ⚠️ يظهر مرة واحدة فقط — احفظه فورًا
  "status": "active",
  "defaultWarehouseId": null,
  "lastEventAt": null,
  "createdAt": "2026-08-08T10:00:00Z",
  "updatedAt": "2026-08-08T10:00:00Z",
}
```

> ⚠️ **لا يمكن استرجاع المفتاح لاحقًا.** إذا ضاع، الحل الوحيد هو تدويره
> (rotate) من نفس الشاشة — وهذا يُبطل المفتاح القديم فورًا.

هذا الـ `apiKey` هو الشيء الوحيد الذي يحتاجه مبرمج المتجر. **لا تستخدم JWT
المستخدم في كود المتجر إطلاقًا** — الـ endpoints الخاصة بالإرسال (ingestion)
تُصادق بالـ API key فقط.

---

## 3. المصادقة في طلبات الإرسال (Ingestion)

كل طلب ترسله من المتجر إلى Cadeau يجب أن يحمل الترويسة:

```
Authorization: Bearer sfk_ab12cdEXAMPLEKEYFULLVALUE...
```

- **لا يوجد JWT هنا إطلاقًا** — هذا الـ endpoint مخصص للأنظمة الخارجية.
- لا ترسل أي حقل باسم `companyId` أو ما شابه — حتى لو أرسلته سيتم تجاهله
  تمامًا؛ الشركة (tenant) تُحدَّد من المفتاح نفسه فقط. هذا إجراء أمني مقصود.
- إذا كان المفتاح خاطئًا أو غير موجود أو تم إبطاله (revoked): `401 UNAUTHORIZED`.
- إذا كانت الميزة غير مفعّلة على خطة الشركة: الاتصال نفسه لن يكون قد أُنشئ
  أصلًا من طرف الـ Owner، فهذا لا يظهر في مرحلة الإرسال.

---

## 4. Base URL والإصدار

جميع المسارات تبدأ بـ `/v1`. مثال بيئة التطوير المحلي:

```
http://localhost:3000/v1/integrations/storefront/...
```

اطلب من فريق Cadeau الـ base URL الفعلي لبيئة الإنتاج/الـ staging الخاصة بك.

## 5. إرسال طلب (Order) من المتجر

```
POST /v1/integrations/storefront/orders
Authorization: Bearer <apiKey>
Content-Type: application/json

{
  "externalId": "store-order-1234",     // رقم الطلب في متجرك — مفتاح idempotency
  "placedAt": "2026-08-08T10:00:00Z",   // ISO-8601
  "customer": {
    "name": "أحمد محمد",
    "phone": "01001234567",              // أي صيغة شائعة — يُطبَّع لصيغة E.164 تلقائيًا
    "email": "a@b.com"                   // اختياري
  },
  "items": [
    { "sku": "SKU-001", "quantity": 2, "unitPriceMinor": 15000 }
  ],
  "currency": "EGP",                    // اختياري
  "notes": "ملاحظة اختيارية"
}
```

### قواعد الحقول

| الحقل                    | إلزامي | ملاحظات                                                                                        |
| ------------------------ | ------ | ---------------------------------------------------------------------------------------------- |
| `externalId`             | نعم    | نص، حتى 200 حرف. **هذا مفتاح التكرار (idempotency key)**.                                      |
| `placedAt`               | نعم    | تاريخ/وقت ISO-8601 صالح.                                                                       |
| `customer.name`          | نعم    | نص، حتى 200 حرف.                                                                               |
| `customer.phone`         | نعم    | أي صيغة — يُطبَّع تلقائيًا.                                                                    |
| `customer.email`         | لا     | —                                                                                              |
| `items`                  | نعم    | مصفوفة، عنصر واحد على الأقل منطقيًا (تحقق من طلبك ألا تكون فارغة).                             |
| `items[].sku`            | نعم    | يجب أن يطابق SKU موجود بالفعل في Cadeau (أنشئ المنتج أولًا عبر `/products` إن لم يكن موجودًا). |
| `items[].quantity`       | نعم    | عدد صحيح ≥ 1.                                                                                  |
| `items[].unitPriceMinor` | نعم    | عدد صحيح، **بأصغر وحدة عملة** (قرش/سنت) — مثلًا 150.00 جنيه = `15000`.                         |
| `currency`               | لا     | كود ISO-4217 (مثل `EGP`).                                                                      |
| `notes`                  | لا     | نص حر.                                                                                         |

### الاستجابة

| الحالة                                                     | متى تحدث                                                                                                                 |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `201 Created` + `{"entityId": "...", "status": "created"}` | أول مرة يُرسل فيها هذا `externalId` بنجاح.                                                                               |
| `200 OK` + `{"entityId": "...", "status": "duplicate"}`    | نفس `externalId` أُرسل من قبل وتمت معالجته بنجاح — **آمن لإعادة الإرسال**.                                               |
| `200 OK` + `{"status": "updated"}`                         | كان هناك محاولة سابقة فاشلة لنفس `externalId` وتمت معالجتها الآن بنجاح.                                                  |
| `422 UNPROCESSABLE_ENTITY` (`UnknownSkuError`)             | أحد الـ `sku` غير موجود في Cadeau. أرسل المنتج أولًا ثم أعد إرسال نفس الطلب بنفس `externalId` — سيُعاد محاولته تلقائيًا. |

**نصيحة عملية:** أرسل دائمًا نفس `externalId` عند إعادة المحاولة (retry) —
هذا يجعل الإرسال **idempotent** بأمان تام: لن يتكرر الطلب في Cadeau مهما
أعدت الإرسال.

## 6. إرسال/تحديث منتج (Product) من المتجر

```
POST /v1/integrations/storefront/products
Authorization: Bearer <apiKey>
Content-Type: application/json

{
  "externalId": "store-product-987",
  "name": "قميص قطن",
  "description": "وصف اختياري",
  "sku": "SKU-001",
  "barcode": null,
  "priceMinor": 15000,
  "stockQuantity": 42,
  "active": true
}
```

### قواعد الحقول

| الحقل           | إلزامي | ملاحظات                                                                                             |
| --------------- | ------ | --------------------------------------------------------------------------------------------------- |
| `externalId`    | نعم    | مفتاح idempotency لهذا المنتج (مرجعي فقط — المطابقة الفعلية بـ `sku`، انظر أدناه).                  |
| `name`          | نعم    | حتى 200 حرف.                                                                                        |
| `description`   | لا     | —                                                                                                   |
| `sku`           | نعم    | حتى 120 حرف. **هذا هو المفتاح الفعلي للمطابقة/التحديث** (فريد لكل شركة).                            |
| `barcode`       | لا     | —                                                                                                   |
| `priceMinor`    | نعم    | عدد صحيح بأصغر وحدة عملة.                                                                           |
| `stockQuantity` | نعم    | **رقم مطلق** (الكمية الحالية بالكامل، وليس فرقًا/دلتا) — Cadeau يحسب الفرق تلقائيًا ويحدّث المخزون. |
| `active`        | لا     | —                                                                                                   |

> **مهم جدًا بخصوص `sku`:** المطابقة/التحديث تتم على أساس `sku` وحده (وليس
> `externalId` + `sku` معًا كما قد تتوقع). يعني إن أرسلت نفس الـ `sku` مرتين
> بقيم مختلفة، سيُحدَّث نفس المنتج — تأكد أن كل SKU في متجرك فريد وثابت ولا
> يُعاد استخدامه لمنتج مختلف لاحقًا.

### الاستجابة

`201` (منتج جديد) أو `200` (منتج موجود) مع
`{"entityId": "...", "status": "created" | "updated" | "duplicate"}`.

### المخزون: أي مخزن يُخصم/يُحدَّث؟

الكمية تُطبَّق على `defaultWarehouseId` الذي حُدِّد عند إنشاء الاتصال، أو
مخزن الشركة الافتراضي إن لم يُحدَّد. لا يوجد حقل لاختيار مخزن مختلف لكل
منتج في هذا الإصدار.

## 7. صيغة الأخطاء الموحّدة

كل استجابة غير ناجحة (4xx/5xx) تأتي بنفس الشكل دائمًا — اعتمد على `error.code`
وليس على نص الرسالة أو رقم الحالة فقط:

```jsonc
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "Request validation failed",
    "statusCode": 400,
    "requestId": "7260f4f1-...",
    "timestamp": "2026-08-08T10:00:00Z",
    "path": "/v1/integrations/storefront/orders",
    "details": [{ "field": "items[0].sku", "messages": ["sku should not be empty"] }],
  },
}
```

| `code`                 | HTTP | السبب الشائع في سياق الربط                                    |
| ---------------------- | ---- | ------------------------------------------------------------- |
| `UNAUTHORIZED`         | 401  | مفتاح API مفقود/خاطئ/تم إبطاله.                               |
| `VALIDATION_FAILED`    | 400  | حقل ناقص أو نوعه خاطئ — راجع `details`.                       |
| `UNPROCESSABLE_ENTITY` | 422  | مثلًا `sku` غير موجود بعد (`UnknownSkuError`).                |
| `TOO_MANY_REQUESTS`    | 429  | تجاوزت معدل الطلبات — انتظر بحسب `Retry-After` وأعد المحاولة. |
| `INTERNAL`             | 500  | خطأ غير متوقع في الخادم — أعد المحاولة لاحقًا؛ لا تكرر بسرعة. |

## 8. الأمان — قواعد إلزامية على فريق المتجر

- **لا تضع مفتاح الـ API في كود الواجهة الأمامية (frontend) أبدًا.** الإرسال
  يجب أن يتم من خادم متجرك (backend/webhook handler)، وليس من متصفح العميل.
- خزّن المفتاح في متغيرات بيئة (environment variables) على خادمك، وليس في
  الكود المصدري.
- إذا اشتبهت أن المفتاح تسرّب: اطلب من مالك الحساب في CRM **تدويره فورًا**
  (rotate-key) — هذا يُبطل النسخة القديمة على الفور دون التأثير على أي
  اتصالات (متاجر) أخرى للشركة.
- إذا توقفت عن استخدام تكامل معيّن نهائيًا: اطلب **إبطال الاتصال (revoke)** —
  إجراء نهائي، سيتطلب إنشاء اتصال جديد لإعادة الربط لاحقًا.

---

## 9. قائمة تحقق سريعة قبل الإطلاق (Go-Live Checklist)

- [ ] المفتاح مخزَّن في متغيرات بيئة على خادم المتجر فقط، غير مكشوف في أي كود frontend.
- [ ] كل طلب Order يحمل `externalId` فريدًا وثابتًا (رقم طلب المتجر نفسه).
- [ ] كل طلب Product يحمل `sku` فريدًا وثابتًا ولا يُعاد استخدامه لمنتج آخر.
- [ ] المنتجات تُرسَل **قبل** الطلبات التي تحتوي على نفس الـ SKU (أو يوجد منطق إعادة محاولة عند `422 UnknownSkuError`).
- [ ] `stockQuantity` يُرسَل كرقم مطلق (الكمية الكلية)، وليس فرقًا.
- [ ] `unitPriceMinor` / `priceMinor` بوحدة القرش/السنت (عدد صحيح)، وليس جنيهات كسرية.
- [ ] الكود يتعامل مع `422`/`429`/`500` بإعادة محاولة آمنة (نفس `externalId`).
- [ ] تم اختبار الربط فعليًا من شاشة **أحداث الاتصال (Events)** في CRM: تحقّق أن الحالة `processed` وليست `failed`.
- [ ] في حال ظهور حدث بحالة `failed`: أصلح السبب (مثلًا أنشئ المنتج الناقص)، ثم استخدم **زر إعادة المعالجة (reprocess)** من CRM بدل إعادة إرسال طلب جديد.

## 10. مرجع سريع للمسارات

| Method   | المسار                                        | من يستخدمه                                                                           |
| -------- | --------------------------------------------- | ------------------------------------------------------------------------------------ |
| POST     | `/v1/integrations/storefront/orders`          | **متجرك** (بمفتاح API)                                                               |
| POST     | `/v1/integrations/storefront/products`        | **متجرك** (بمفتاح API)                                                               |
| GET/POST | `/v1/integrations/storefront/connections/...` | فريق CRM فقط (JWT + صلاحية `integrations.manage`) — لإدارة المفاتيح ومتابعة الأحداث. |

للتفاصيل الكاملة لكل مسار إداري (إنشاء/تدوير/إبطال الاتصال، عرض الأحداث،
إعادة المعالجة) راجع [docs/api/storefront.md](api/storefront.md).
